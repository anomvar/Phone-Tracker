# API Reference

Base URL: `http://localhost:8080` (dev) or the configured host/port in production.

- All endpoints are **token-gated** except `POST /api/auth/login` and `GET /api/health`.
- Send the session token as an HTTP header: `Authorization: Bearer <token>`.
- While `must_change_password` is true for the account, data endpoints return `403` with header `X-Auth-Flow: change-password`.
- Bodies are JSON. Errors use standard FastAPI shapes, e.g. `{"detail": "..."}` with the HTTP status code.
- Interactive OpenAPI docs (generated by FastAPI): `/docs`.

## Authentication

### POST /api/auth/login
Authenticate and obtain a session token.

Request body:
```json
{ "username": "admin", "password": "admin123" }
```

Responses:
- `200`:
  ```json
  {
    "token": "<hmac-signed-token>",
    "username": "admin",
    "role": "admin",
    "must_change_password": true
  }
  ```
- `400` — missing username/password.
- `401` — invalid credentials, or account locked with `{"detail": "Account temporarily locked · retry in 5s"}`
  (lockout: 5 failures within 300 s).

### GET /api/auth/me
Return the current user's profile.

Response:
```json
{
  "username": "admin",
  "role": "admin",
  "must_change_password": false,
  "created": "2026-07-17T00:00:00Z"
}
```

### POST /api/auth/change-password
Change the current user's password. Clears failed-login counters.

Request body:
```json
{ "current_password": "old", "new_password": "NewPass12345" }
```

Constraints on the new password: ≥10 chars, must contain letters **and** digits.

Responses: `200 {"ok": true}`; `400` if current password is wrong or new password is weak.

## Admin — user management (role: `admin`)

### GET /api/admin/users
List all users (passwords are never returned).

```json
[
  {
    "username": "admin",
    "role": "admin",
    "must_change_password": false,
    "created": "2026-07-17T00:00:00Z",
    "created_by": "system"
  }
]
```

### POST /api/admin/users
Create a user.

```json
{ "username": "jdoe", "password": "Jdoe12345", "role": "analyst" }
```

Responses: `200 {"ok": true, "username": "jdoe", "role": "analyst"}`; `400` invalid role / weak password; `409` user exists.

### PATCH /api/admin/users/{username}
Update role and/or reset password. Either field is optional; a password reset sets `must_change_password: true`.

```json
{ "role": "admin" }
```
```json
{ "password": "NewStrong123" }
```

Responses: `200 {"ok": true}`; `400` invalid role / weak password; `404` user not found.

### DELETE /api/admin/users/{username}
Delete a user. Cannot delete your own account.

Responses: `200 {"ok": true}`; `400` self-delete; `404` user not found.

## Case & target data

### GET /api/health
Unauthenticated. Reports service status and case sizes.

```json
{
  "ok": true,
  "auth": "required",
  "cases": { "erakshak": 4, "fir47": 28 }
}
```

### GET /api/cases
List registered cases.

```json
[
  { "id": "erakshak", "label": "E-Rakshak", "subtitle": "Hackathon CDR · Multi-operator", "targets": 4 },
  { "id": "fir47", "label": "FIR 47", "subtitle": "NCCRP 222/2024 · Surat Cyber · Mora↔Jahangir", "targets": 28 }
]
```

### GET /api/targets?case={case_id}
List all targets in a case (`case` defaults to `erakshak`). For `fir47`, corridor movers sort first.

Each item is a target summary + stats; see [DATA_MODEL.md](./DATA_MODEL.md#target-summary).

### GET /api/targets/{msisdn}?case={case_id}
Full target detail: summary, stats, towers, and the full computed track.

```json
{
  "msisdn": "9714499703",
  "operator": "Airtel",
  "label": "Airtel · Surat",
  "ping_count": 123,
  "tower_count": 8,
  "t_start": "2026-06-01T00:00:00",
  "t_end": "2026-06-01T23:59:59",
  "bbox": { "min_lat": 21.0, "max_lat": 21.2, "min_lon": 72.7, "max_lon": 72.9 },
  "center": { "lat": 21.1, "lon": 72.8 },
  "stats": { "avg_shift_m": 421.3, "avg_refined_conf_m": 156.2, "pct_trilateration": 62.5, "points": 123 },
  "towers": [ { "cgi": "...", "lat": 21.1, "lon": 72.8, "name": "", "operator": "Airtel", "hits": 40 } ],
  "track": [ { "ts": "...", "lat": 21.1, "lon": 72.8, "alt_m": 0, "confidence_m": 100.0,
               "method": "trilateration", "towers_used": ["..."], "raw_lat": ..., "raw_lon": ...,
               "speed_mps": 3.2, "heading_deg": 90.0, "cgi": "...", "gap_m": 0, "gap_s": 0,
               "session_id": 0, "is_gap_start": false } ]
}
```

For `fir47` targets the summary additionally includes `name`, `sites`, `corridor`, and `case`.

### GET /api/targets/{msisdn}/towers?case={case_id}
Just the tower list (`towers` array above).

### GET /api/targets/{msisdn}/track?case={case_id}
Just the track (`track` array above).

## Reports

Report payloads are defined in [DATA_MODEL.md](./DATA_MODEL.md#reports).

### GET /api/reports/case/{case_id}
Case-level intelligence report. Adds `generated_at` and `generated_by`.

### GET /api/reports/target/{msisdn}?case={case_id}
Single-target intelligence report.

### GET /api/reports/export/target/{msisdn}.csv?case={case_id}
CSV export of the raw fix track (`Content-Disposition: attachment; filename="{msisdn}_track.csv"`).
Columns: `index, timestamp, lat, lon, alt_m, confidence_m, method, cgi, towers_used, speed_mps, speed_kmh, heading_deg, raw_lat, raw_lon, gap_m, gap_s, session_id`.

### GET /api/reports/export/target/{msisdn}.json?case={case_id}
JSON export: target payload + towers + track + full target report.

### GET /api/reports/export/case/{case_id}.csv
Case summary CSV (`filename="{case_id}_summary.csv"`).
Columns: `msisdn, name, operator, ping_count, tower_count, start, end, distance_km, max_speed_kmh, avg_confidence_m, tri_pct, sessions, sites, corridor`.

### GET /api/reports/export/case/{case_id}.json
JSON export of the case report.

## WebSocket — live playback

### WS /ws/live/{msisdn}?case={case_id}&token={token}

Browsers cannot set WebSocket headers, so the session token is passed as a query parameter. Invalid/missing token → `{"type":"error","message":"unauthorized"}` then close code `4001`.

Server → client messages:

| type | fields | meaning |
|------|--------|---------|
| `init` | `target`, `stats`, `towers`, `total` | Track metadata, tower list, fix count |
| `fix` | `index`, `total`, `fix` | One refined fix to render |
| `complete` | `total` | Playback finished |
| `error` | `message` | Error (e.g. `unknown target`) |

Client → server commands (JSON text frames):

| cmd | fields | meaning |
|-----|--------|---------|
| `play` | — | Start / resume playback |
| `pause` | — | Pause playback |
| `speed` | `value` (float) | Playback multiplier (default 8.0) |
| `seek` | `index` (int) | Jump to a fix index |
| `reset` | — | Back to index 0, playing |

Default pacing: one fix every 0.35 s at speed 8.0; `interval = 0.35 / max(speed/8, 0.25)` clamped to ≥0.05 s.
